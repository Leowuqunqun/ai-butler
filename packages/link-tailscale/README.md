# @butler/link-tailscale

`ctx.link` 的**第二个真实现**：跨网链路。

中枢和节点不在同一个网络里时用它 —— 家里那台和公司那台，各自连上同一个尾巴网络
（Tailscale），中枢就能指到另一台。

## 先说清楚它不是什么

**它没有自己的一套线协议。** 线上跑的**还是 `link-lan` 那套 HTTP + SSE**，
一个字都没改。换掉的只有一件事：

> **怎么找到那台机器。**

| | `link-lan` | `link-tailscale` |
| --- | --- | --- |
| 名册哪来的 | 你手写在配置里的 `peers` + 配对收下的（落盘） | 问 Tailscale：谁在我的网络里 + **配对收下的那部分**（落盘） |
| 地址怎么来 | 手填的局域网 IP | 尾巴地址（`100.x.y.z`），换网、换 IP 都不变 |
| 谁算"我的节点" | 配了就算 | **探一下**：答得上来的才算 |
| 适合 | 两台机器在同一个 WiFi | 中枢和节点不在一个网络里 |

所以它**只装在中枢那台**。被遥控的那台照旧跑 `butler node`
（`@butler/link-lan/node`），配置一个字都不用改 —— 它本来就听在 `0.0.0.0`，
尾巴网络给了它一个地址，它就在那儿了。

## 配置

```jsonc
{
  "link": {
    "tailscale": {
      // **可以不填。** 跨网这条推荐走「配对」：不填密钥，设备一台台收进来，
      // 每台带一把它自己的密钥（理由见下面"安全"）。
      // 填了就是老路子：拿这一把去探整张尾巴网络，答得上来的都算节点。
      "secret": "",

      "binary": "tailscale",   // CLI 在哪。装好了就不用改
      "port": 41338,           // 节点那台听哪个端口（所有节点用同一个）

      "ownOnly": true,         // 只认你自己账号下的设备（公司尾巴网络里别去骚扰同事的机器）
      "cacheMs": 5000,         // 名册缓存多久。微信里每说一句都要认一次路
      "cliTimeoutMs": 4000,    // 问一次 CLI 最多等多久
      "pingTimeoutMs": 800,    // 探一台最多等多久
      "idleTimeoutMs": 120000  // 多久没动静算掉线（是"空闲"不是"总时长"）
    }
  }
}
```

## 用户那边要做什么

1. 两台电脑都装 [Tailscale](https://tailscale.com/download)，**用同一个账号登录**。
2. `butler init --link tailscale`（中枢那台）—— 配置里**不用填密钥**。
3. 节点那台照旧 `butler node --config …`：它会在屏幕上打出一行
   「配对 100.101.102.103:41338 4A7-K2M」。
4. **把那一行发到微信里**，中枢就认得这台了。

就这样。不用记 IP、不用配端口映射、不用在路由器上开洞，
**也不用在两台机器上把同一串密钥抄对**。

### 配对：跟局域网那条是同一套

那台电脑屏幕上那一行就是全部凭据。中枢拿它去换回那台机器**自己的**身份和密钥
（`link.pair`，走的是 `link-lan` 那条一模一样的握手）—— 密钥只在这一条链路上
从节点流向中枢，**微信那边自始至终没看见过它**。配对码一次性、会作废。

配过的关系**当场落盘**（默认 `~/.butler/state/tailscale-peers.json`，0600），
所以中枢重启之后名册还在，那些没开机的照样显示"离线"而不是凭空消失；
想撤回就说「忘掉 家里那台」。

> 尾巴地址（`100.x.y.z`）在 macOS 上走的是 `utun` 网卡。所以
> `localAddresses()` 特意**不滤** `utun/tun/tap`（只滤容器和网桥）——
> 不然节点屏幕上打不出那句能抄的话，跨网配对就没法指路。

### 老路子还在：一把共享密钥探全网

配置里填了 `secret` 就还是原来的行为：拿这一把去探整张尾巴网络，
答得上来的都算节点（名册在 Tailscale 手里，不落盘）。
这条路不用配对，适合"几台机器一把密钥、自己心里有数"的用户。

## 它是怎么找到机器的

```
tailscale status --json            ← 问一句：谁在我的网络里，谁在线
        ↓  只留自己账号下的、有 IPv4 尾巴地址的
   候选名单（可能是打印机、NAS、同事的电脑……）
        ↓  对每台探一次 link.ping（带密钥、带超时）
   答得上来的 = 管家节点            ← id / 别名 / 能力**是节点自己报的**
        ↓
   变成 ctx.link 里的 DeviceInfo
```

两个刻意的判断：

- **答不上来的不算节点。** 尾巴网络里大部分设备不是管家。它们不是"离线的节点"，
  它们根本不是节点，所以不会被列进"我知道的设备"里。
- **报出来的 id 和别名来自节点自己**，不来自 Tailscale 的机器名。
  这样 `@家里那台` 在两台机器上的意思是一致的。

**配对收下的**节点记在名册文件里：那台关机之后微信里仍然看得见
"家里那台（离线）"，**中枢重启也还在**（`lastSeen` 也还在）。
探全网探到的那些只在进程内存里 —— 名册本来就归 Tailscale 管，
不值得再抄一份。

## 安全边界

**密钥仍然是第二道门 —— 只是现在每台一把。** 有人会问：Tailscale 自己已经用
WireGuard 把网络封住了，为什么还要密钥？因为这是两件事：

- Tailscale 回答的是"**谁能进这个网络**"；
- 密钥回答的是"**谁能遥控你这台电脑**"。

你的尾巴网络里可能有家人的设备、可能开着 subnet router 或 exit node、
可能哪天临时加进来一台机器。密钥是第二道门，而它现在几乎不花用户什么力气
——**配对时由节点自己交给中枢**，用户不用知道它存在，也不用在两台机器上抄同一串。
一台泄漏不等于全都泄漏。

另外两条跟 `link-lan` 一样的红线：认证在**读第一个字节之前**完成，
密钥比较用**常量时间**。

## 几个刻意的选择

- **只用 IPv4 的尾巴地址。** `TailscaleIPs` 通常给两条（`100.x` 和 `fd7a:…`）。
  IPv6 那条在 `fetch` 里要加方括号、还可能被本机的 IPv6 策略影响 ——
  多一类失败原因不值得。**纯 IPv6 的尾巴网络现在不支持**，这种情况会明确报出来。
- **`ownOnly` 默认开着。** 公司尾巴网络里可能有几十台机器，全探一遍是骚扰；
  把同事的电脑列成"我的设备"更是错的。
- **撞名当场报错。** 两台电脑的节点 `id` 一样（抄配置忘了改）会**安静地指错机器**，
  所以在发现阶段就说清楚。判据是"**尾巴设备 id**"而不是地址 ——
  地址只是"怎么够得着"，尾巴设备 id 才代表一台机器。
- **`check()` 是异步的。** 自检要问 CLI，所以得 `await`。
  `ctx.link` 的 `check()` 本来就允许 `Promise | 同步` 两可 —— 结论是**不用改 seam**。
  自检**故意不探节点**，跟 `link-lan` 一致：那台没开是"你没开电脑"，不是"配置错了"。

## 换一条链路，内核一行都不用改

这是这个包存在的**真正理由**：验证 `ctx.link` 这个 seam。

`cli/test/m2-e2e.mjs` 里那四条 M2 验收标准
（`@家里那台` 真的在那台上干活、那台产出的文件真的回传、
那台关掉之后给一句人话、名字叫错时列出真正存在的设备）——
**在局域网链路和尾巴网络链路上，断言一个字都不用改**，跑的是同一套用例。
中枢侧只是把 `ctx.link` 的实现换了一个，`@butler/core` 没有任何改动。

## 还没做的

- **纯 IPv6 的尾巴网络**不支持（见上）。
- **一把共享密钥探全网**这条老路上，所有节点得用同一个端口
  （那条路没有"每台自己的地址和密钥"这回事）。配对收下的设备不受这条限制：
  它连端口都是配对时自己报的。

## 开发

```bash
pnpm build       # tsc
pnpm test        # 34 个用例
```

34 个用例里，32 个离线就够（传输层用假 CLI 顶掉，真节点、真 HTTP 往返），
**2 个真的去问本机的 Tailscale**：读这台机器真实的 `tailscale status --json`，
再把一个真节点听在 `0.0.0.0`，**从本机的尾巴地址连过去** —— 流量真的走了 tailscale0。
没装 Tailscale 的机器上这两个会跳过。

真 CLI 的输出形状是用真机抓下来当夹具钉住的（`test/tailnet.mjs`），
以后 Tailscale 改字段，这里会先红。
