# @butler/approval-im

`ctx.approval` 的第一个实现：**把"要动你的电脑"问进对话里**。

dsh 在动你的电脑之前会问一声。这个包让那个问号变成微信里的一条消息：
主人回「允许」才放行，**到点没人答就是不许**。

## 两个入口，两个进程

| 入口 | 跑在哪 | 干什么 |
| --- | --- | --- |
| `@butler/approval-im` | 管家进程 | `ctx.approval`：念清单、把答复落回去 |
| `@butler/approval-im/answerer` | dsh 子进程 | 接住 `approval/request`，等主人的答复 |

两边**不共享内存**，只共用 `<home>/state/approvals/` 这个目录：

```
<home>/state/approvals/
  pending/<id>.json      一件事在等（0600）
  pending/<id>.answer    它已经有结论了（0600）—— 唯一凭据，结算时不删，24 小时后清
  approvals.jsonl        账本：谁批的、批了什么、什么时候（0600）
```

`<id>.answer` 用 `O_EXCL` 写：**同一次审批只可能有一个赢家**，
所以账本里不会出现两行互相矛盾的记录。

## 四种结局（照 dsh 的封闭词表）

| 结局 | 什么时候 |
| --- | --- |
| `allowed-once` | 主人说「允许」—— **只此一次**，不做通配授权 |
| `rejected` | 主人说「不许」，**或者到点没人答** |
| `cancelled` | 对方撤回了这次调用（`signal` 中止） |
| `unavailable` | 连问题都没记下来（盘不可写等）→ 让 dsh **按拒绝处理** |

`unavailable` 是关键的一条：记不下来就是问都没问成，绝不能"那就当允许吧"。
这条有测试盯着（拿一个**文件**当目录的父路径，`mkdir` 必失败）。

## 主人看到什么

```
【有件事要动你的电脑，等你一句话（118 秒内）】

1. 删除 ~/下载/旧项目（bash）

回「允许」或「不许」就行。
到点我不等到答复，就当不许 —— 不会先做了再说。
```

「允许 1」「不许 2」按编号指名。**编号只按主人看过的那份清单算** ——
清单变了（过期了一件、又来了一件）内核会重新念一遍，绝不拿旧编号猜是哪一件。
这条也在 `@butler/core` 的测试里钉着。

## ⚠️ 有一根线只能在真机上验

`butler init` 生成的 dsh 补丁末尾会追加一行应答者，指向
`@butler/approval-im/answerer` 的**绝对路径**。子进程能不能 import 到它，
取决于安装布局 —— 这一条**只有真跑一次 dsh 才能确认**（需要真的模型 key）：

```bash
butler doctor                     # 看 approval 那一行在不在
# 然后让它干一件会被判定为敏感的事，微信里应当弹出上面那条问句
```

装上不成的后果是安全的：dsh 的兜底是 `unavailable` → fail-closed → 一律不许，
**不会卡住**（这一点是读 `@deepseek-ai/dsh-user-approval` 的 `decide()` 确认的，
补丁里以前那句"会无限期等待"已经不成立了）。

协议本身（两个进程、四种结局、超时=不许、单写者）全部离线测过，见 `test/`。
