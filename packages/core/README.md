# @butler/core

AI 管家的**内核**：把 `ctx.channel` 收到的消息交给 `ctx.agent`，再把结果发回去。

```
手机 ──微信──> ctx.channel ──> 本内核 ──> ctx.agent ──> 这台电脑
                                  │
                                  ├── ctx.link ──> 别的电脑（你 @ 了才走）
                                  └── 认人、认路、排队、进度、回话
```

内核**只认能力位，不认微信、也不认 dsh**：换通道、换大脑都不用改它一行代码。
两个是必需的（`ctx.channel` / `ctx.agent`），`ctx.link` 是**可选**的 ——
只有一台电脑的人不装链路，这个包照样跑。

## 它负责的六件事

| | 为什么 |
|---|---|
| **认人** | 只有主人能让这台电脑干活。名单配了就用名单，没配就**第一次说话的人认主**（只认一次，顶不掉）。通道里那个 `allowFrom` 只是粗筛，**这里才是真正的门** |
| **排队** | agent 是"一问一答"，前面没跑完不会跑下一条。排队时说清楚前面还有几条；积压超上限就**明确拒收**，不静默丢 |
| **让等待可见** | agent 一跑可能几分钟。不发"正在输入"、不报进度的话，用户看到的就是"没反应"。每隔一段时间会播报"还在处理（已 Ns）"，并带上 **agent 最近一条进度** |
| **如实回话** | 出错就说错在哪，没出结果就说没出结果。**静默失败是禁止的** |
| **认路** | 默认在**这台电脑**上办；只有 `@别名` 才跨设备。见下一节 |
| **自己记事** | 你说过的长期偏好记在 `ctx.memory` 里；**管家自己在回答里写下** `[[记住: 一句话]]` 也会被记下，而且当场告诉你一声 |

## 跨设备：`@别名`

产品上定死了一条：**默认目标是中枢所在的那台，显式指定才跨设备，不做隐式猜测。**

```
把桌面理一理              → 在这台电脑上办
@家里那台 把桌面理一理      → 送到「家里那台」上办
家里那台好像坏了           → 还是在这台电脑上办（这是**话**，不是**命令**）
```

为什么不做"话里提到就送过去"？因为那不是聪明，是**危险**：
主人说一句"家里那台好像坏了"，隐式匹配会把这句**话**当成**命令**
发到那台机器上去执行。所以只有一种触发方式：**某一行以 `@` 开头**。

没有 `@` 就一个字都不多想，直接在本机办 —— 这条路上**一次网络都不发**。

### 在微信里管理这些设备（配对 / 设备 / 忘掉）

设备是**配对**收进来的，整个过程都在微信里完成 —— 不用去改配置文件：

| 你说 | 它做什么 |
| --- | --- |
| `配对 192.168.1.9:41338 4A7-K2M` | 收下那台电脑。配对码是**那台电脑屏幕上**打出来的，只能用一次 |
| `设备` | 现在认识哪些电脑、在不在线、最后在线多久前 |
| `忘掉 家里那台` | 不再管那台电脑（手写在配置文件里的那台忘不掉，会告诉你去哪删） |
| `帮助` | 把这几个词列一遍 |

三条是**刻意的**：

1. **这些词不交给 agent。** 一句话送到模型那里，它就可能被"说服"去改权限 ——
   而 `配对` 是权限变更。内核先看是不是命令，是就自己处理，一个字都不发给模型。
2. **不像命令的话原样落到 agent。** 「设备都没了」「帮我看看忘掉密码怎么办」是**话**，
   不是命令：认不出来就一个字都不动。这条边界有一堆用例专门钉着，
   包括"半个命令"—— 只打「配对」两个字时它当然还是命令，只是提醒你参数不够。
3. **只报结论，不报栈。** 配对失败会说清是哪一种（码不对 / 已经用过了 / 过期了 /
   够不着那台电脑 / 那台电脑没理我），因为用户要做的下一件事各不相同。

链路那一侧不支持配对时（比如尾巴网络那条），它会直说"这条链路不用配对，
发「设备」看看"，而不是给一个空白的失败。

### 说错的时候，它怎么答

用户唯一要学的就是"`@` + 名字"，所以名字打错时必须自己兜住：

| 你发的 | 它回的 |
|---|---|
| `@同事的电脑 帮我看看` | 没有叫「同事的电脑」的设备。我知道的是：家里那台、公司电脑（不在线） |
| `@家里那台` | 你想让「家里那台」做什么？ |
| `@家里那台 …`（那台关机了） | 连不上家里那台（最后在线 21:59:45）。它可能关机了，或者不在同一个网络里 |
| `@家里那台 …` + 附件 | 附件现在还送不到「家里那台」上（这个功能还没做）… |

最后一条是刻意**拒绝**的：附件在中枢这台机器上，只把话发过去的话，
那边的 agent 会拿到一个**它根本不存在的路径**，然后一本正经地失败。

### 那台机器上产出的文件，怎么回到微信

节点上的 agent 说"我生成了一个报表"——那个路径**在这台机器上不存在**。
所以内核不接路径，只接一张**取件凭证**（对方铸的），拿它去把字节一块块取回来，
落成本机的一个临时文件，再交给 `ctx.channel.sendFile`。

```
对面：files: [{ token: 'a3f…', name: '报表.xlsx' }]
内核：file.read(token, offset=0) → file.read(…, 524288) → … → 本机临时文件 → 微信
```

两条不做让步的规矩：

- **取回来才算数。** 取不回来的文件，会在回复后面如实写清"有 1 个文件没取回来：报表.xlsx（…）"，
  **绝不假装发出去了** —— 用户以为发出去了、其实没有，是最坏的情况。
- **半截文件不发。** 传到一半断了就删掉，宁可报错，也不能把一个残缺文件发出去让用户以为文件是好的。

### 切名字的规则

中文句子常常不加空格，所以**先用已知别名做最长匹配**，匹配不上再退回
"`@` 后面第一个词"。这样 `@家里那台把桌面理一理` 也切得开。
另外**扫所有行**而不只看第一行 —— 用户引用某条消息再 @ 时，`@` 不在第一行。

### 会话按设备分开记

同一句"把那个文件改一下"，在这台电脑上和在家里那台上说的是**两件事**。
所以账本里两个会话各记各的（`node-home#u1` / `u1`），**绝不串**。
本机那条沿用老的键位 —— 已经在跑的管家升级上来不会丢会话。

## 用法

```ts
await ctx.plugin(WechatChannel, { home: '~/.butler' });   // ctx.channel
await ctx.plugin(DshAgent, { profile: 'headless' });      // ctx.agent
await ctx.plugin(ButlerCore, {
  workspace: '/Users/me/work',
  stateFile: '~/.butler/state.json',
});

await ctx.core.start();     // 加载 ≠ 上线，start() 才真的开始收信
```

`ctx.core` **不是**那 5 个能力位之一（能力位是"可替换的零件"）。
它是**应用自己**：一个进程里只有一个，注册成服务是为了让命令行、
`doctor` 这些地方能拿到它问状态、叫它启停。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `workspace` | `''` | agent 在哪干活。空 = 进程当前目录 |
| `allowFrom` | `[]` | 谁能遥控。**空数组 = 第一个说话的人认主** |
| `stateFile` | `''` | 账本（主人 + 会话）落到哪。空 = 只记内存，重启就忘 |
| `maxQueue` | `5` | 最多积压几条。超了明确拒收 |
| `progressIntervalMs` | `40000` | 多久播报一次"还在处理"。`0` = 不报 |
| `quoteReply` | `true` | 回话时把"在回哪句"交给通道（微信顶一行 `↩ 原话`，Telegram 走原生引用）。内核自己不拼文本。**规则**：终结性回复（答复/出错/拒收/命令结果/附件）引用，过程性消息（进度播报、队列回执）不引用；只发附件没说话时退回一句附件描述 |
| `typing` | `true` | 发"正在输入" |

## 生命周期

- **加载 ≠ 上线。** 构造函数只做接线（订阅通道消息），要显式 `start()` 才收信。
- **`start()` 幂等。**
- **`stop()` 不等在跑的那一轮跑完** —— agent 一跑可能几分钟，用户按了 Ctrl-C
  就是要现在停。在跑的那轮会被 `signal` 掐断。
- 卸载 `ctx` 时自动收尾（停通道、摘消费者、停 worker），走 `ctx.effect`。

## 几个设计决定

**为什么会话记忆先自己实现、不用 `ctx.memory`？**
那个能力位要到 M2 才建。按已定的原则——**没有实现的能力位不提前建**——
先用一个最小实现顶上（`src/sessions.ts`），接口形状照着将来 `ctx.memory`
的用法设计，换过去时调用方不用改。

**`SESSION_LOCKED` 为什么是类型化的错误码？**
因为核心层要**按原因决定怎么恢复**（丢掉旧会话、开新的重试一次），
而不是去匹配错误文案——匹配文案那种写法，改一个字就悄悄失效了。
见 `AgentErrorCode`。

```bash
pnpm test        # 一百六十多个用例，全离线
```

| 文件 | 验什么 |
| --- | --- |
| `test/core.mjs` | 内核本来的那些：依赖门控、加载≠上线、排队与上限拒收、进度播报、停机掐断…… |
| `test/route.mjs` | **认名字这件事本身**（纯函数）：显式才认、中文不加空格、最长别名、引用行、缩进 |
| `test/routing.mjs` | **认路的端到端**：该发到远端的发了、不该在本机跑的一次都没跑、会话不串、远端文件真的取回来、各种说错的情形 |
| `test/commands.mjs` | **微信里那几个词**：真内核 + 假链路跑一遍配对/设备/忘掉/帮助，以及最要紧的那条边界 ——「像话的不当命令、像命令的不惊动 agent」 |

假通道 / 假 agent / 假链路都**真的继承了那三个 seam 的类**，所以这里验证的是
"接线真的通、边界真的守住了"，而不是"凑合能跑"。

每一条路由用例都尽量同时验两件事：**该发生的发生了**，
和**不该发生的一点都没发生** —— 后者才是这类功能真正会出事的地方
（把话偷偷发到不该去的机器上）。

## 记忆：怎么自己记，又怎么保证不错记

主人明说「记住 …」是一条路；另一条路是**管家自己在回答里写一行** `[[记住: 一句话]]`
（跟 `[[file:…]]` 同一个思路，但这条由内核认，因为记忆归内核管）。

为什么用标记法，而不是每轮再调一次模型来"抽取记忆"？后者又慢又贵，而且抽错了
说不清是哪一步错的。标记法把这件事放进**本来就要发生的那一次回答**里。

**铁律：宁可漏认，不可错认。** 认错一条记忆比少认一条坏得多 —— 它会跟着**每一轮**
请求走，悄悄影响之后所有回答，而主人根本不知道自己在跟一条错记忆说话。所以：

| 认（记账） | 摘（发出去的话） |
|---|---|
| 只认**整行就是标记**这一种写法 | **任何位置**出现的标记都摘掉 |
| 一次最多一条，多了认最后一条 | 空的/超长的/套着另一个标记的也照摘 |
| 空、超长、套标记的**一条都不记** | 认不认是记账，摘不摘是别让他看见黑话 |

记账失败**绝不连累回答**（软失败）：主人要的是答案，不是一条"记忆写不进去"的报错 ——
那种报错只会让他以为活也没干成。关掉它的开关是 `autoMemory`。
