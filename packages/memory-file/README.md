# @butler/memory-file

[`ctx.memory`](../seam-memory) 的第一个实现：**一个 JSON 文件**。

```json
{ "version": 1,
  "entries": {
    "简历放哪": { "value": "Documents/简历/", "kind": "preference",
                  "createdAt": "…", "updatedAt": "…", "seq": 7,
                  "source": "owner", "note": "记住：简历都放 Documents/简历/" }
  },
  "nextSeq": 8 }
```

落在 `~/.butler/state/memory.json`（`home` 可以配；`file` 可以直接指定整个路径）。

## 三个不显然的决定

**每次调用都读文件，不做内存缓存。** 量小；而且 `butler doctor` 是**另一个进程**，
管家正跑着的时候它也要能报"记住 3 条"。缓存省下的那点时间，换不来两边各记一份的麻烦。

**顺序靠 `seq`，不靠时钟。** `list()` 的契约是"新的在前"，而"忘掉第 2 条"要靠这个顺序。
只按 `updatedAt` 排，同一毫秒写的两条会并列 —— 用户就可能删错一条。`seq` 每次写 +1，
顺序因此是确定的；它只存在文件里，不对外暴露。

**文件坏了要拦下来，不许当空的。** 当空的现象是"我记住的东西全没了"，
而且没有任何线索 —— 比直接报错还难查。所以会抛，并且说清**哪个文件、怎么修**
（删掉重来，或改名留档）。单条坏了只丢那一条，不连累整份。

## 隐私

记忆里会有"我的工作目录是 ~/work"这种内容。目录 `0700`、文件 `0600`、**原子写**
（临时文件 + rename，别让一次断电毁掉全部记忆）。
