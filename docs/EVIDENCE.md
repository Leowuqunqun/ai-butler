## 最有分量的几条证据

- `agent-dsh` 的最后 7 个是**端到端**的：真 `core` 驱动真 `DshAgent` 驱动真子进程。
- `cli` 的最后 6 个是**真实组合**：真的三个插件（真微信通道 + 真内核 + 真 dsh agent）
  装进同一个容器，三条能力位齐、配置端到端传到。
- `link-lan` 的 65 个里有 **47 个真的起了一个 HTTP 节点**（或真跑了一次完整往返）：
  真监听、真认证、真用 `ctx.link` 连过去、真跑一次带进度的调用。其中 5 个专盯
  "一句话说不清楚的失败"（空闲超时、半路掉线、密钥不对、协议版本对不上、方法不存在）
  —— 这些才是用户会遇到的。
- `cli` 里那 7 个是**真的 spawn 了一个 `butler node` 进程**：真读配置文件、真开端口、
  中枢连过去、进度真的跨进程回来、`Ctrl-C` 退得体面（退出码 0）。
- `cli` 里还有一条 **M3 的验收**：在一个**刚建出来的空家**里跑一次 `butler init`，
  再跑 `butler doctor` —— 五个插件真的装得上、五条能力位真的齐，
  而它说出来的唯一一件事是"还没登录微信"。**配置是程序写的，所以名字不可能是错的。**
- `cli` 里还有一条 **M3 安装器的验收**：把**真正要发出去的那个包**（`dist/*.tar.gz`）解开，
  在一个**临时家目录 + 临时前缀**里走完"dry-run → 真装 → `--help` → `init` → `doctor` →
  `autostart --dry-run` → 没 Node 的 PATH 下照样能跑 → 卸载留数据"这 18 项（`sh scripts/verify-clean-install.sh --no-node`
  再加 1 项：**把 node 从 PATH 里整个拿掉**，看它会不会自己去下一份、校验官方 SHA256、并用壳脚本把那份钉住 ——
  这是真机上最常见、平时又最难测到的一种机器）—— 真 `~/Library`、真 launchd、真微信一个都没碰。
  **它第一次跑就抓到了上一张表里那个 ★ bug**，这就是它存在的理由。
- `channel-wechat/test/login.mjs` 那条 ★ **真起了一个本地 HTTP 扫码页**（只监听 127.0.0.1），
  喂一个假客户端走完整条登录：码真的进了页面、浏览器真的被指向页面那个地址、
  登录态真的落了盘、游标真的被清掉、收场真的把页面关掉 —— 一条网都没连。
- **M2 的验收标准本身有测试**（`cli/test/m2-e2e.mjs`，**同一套用例跑两种链路**）：
  中枢是真内核 + 真链路插件，节点是真 `butler node` **子进程**，中间隔一次真实的 HTTP + SSE 往返 ——
  微信里说 `@家里那台 …`，**那台机器上的 agent 回话，本机 agent 一次都没跑**；
  说 `@家里那台 把那个文件发我`，**那台电脑上写出来的文件真的落到了中枢这台机器上、
  字节一模一样**；把那台关掉再 @ 它，得到的是一句人话而不是装死。
  **换成 `link-tailscale`（名册问 Tailscale 要、地址换成尾巴地址），这四条的断言一个字都不用改**
  —— `ctx.link` 这个 seam 是真的还是纸糊的，看的就是这个。
- `link-tailscale` 的 22 个里有 2 个是**真机**：读这台机器真实的 `tailscale status --json`，
  再把一个真节点听在 `0.0.0.0`，**从本机的尾巴地址连过去**（流量真的走了 tailscale0）。
- **配对那一条路是端到端钉住的**（`cli` 里那个带 ★ 的用例，也是这一轮的核心验收）：
  配置里**不写 id、不写密钥**（小白那份配置本来的样子）→ 真进程起来，屏幕上打出
  「配对 127.0.0.1:41338 4A7-K2M」→ 中枢拿着这一行收下 → **真的能在那台电脑上干活**。
  同一个用例还钉了另外两件：中枢自己**一把密钥都没有**（密钥是配对时从那台机器换回来的），
  以及那个码**只能用一次**（再用会被明确告知"已经用过了"，而不是又发一遍密钥）。

这就是"**十个包、三条 seam（`ctx.channel` / `ctx.agent` / `ctx.link`）真的合得上**"的证据 —— 不再是图纸。

## 为什么开发那一堆检查存在

**测试是刻意做成离线可跑的**：微信媒体那部分自己伪造 CDN 密文、自己跑 AES 解密来验证，
所以不需要真账号、也不会给谁发消息。CI 在 Node 20 / 22 / 24 三个版本上跑全套。

> `check:docs` 里有一条专门查「**引用了被 gitignore 的文件**」——
> 本地看着一切正常、推到 GitHub 却是裂图。这类问题不查就一定会漏。
>
> `check:packages` 是**被真事故逼出来的**：`files` 里一个一个列文件名，漏掉一个编译产物，
> 现象是"装得上、装完起不来"（`Cannot find module '…/lib/sessions.js'`）——
> 仓库里一切正常，因为源码就在手边。现在规矩是**整目录进包**，由这个脚本守。
>
> `mutate` 问的是另一个问题：**"测试全绿"到底是不是真绿。** 它把每一处承诺故意改坏，
> 看有没有用例喊疼 —— 不喊疼的那些，就是"只在文档里成立的承诺"。
> 它**故意不进 CI**（十几分钟，且会在一份副本里反复重编）：它是你想验"测试本身"时才跑的。
> 第一版用 `cp -al` 硬链接当副本，写文件截断的是同一个 inode，变异**漏回了原仓** ——
> 所以现在副本必须是真副本（逐文件比对 inode），原仓还有哈希绊线盯着。
