## 定位

**一个住在你电脑里、用微信跟你说话的管家。**

你说要什么，它替你操作电脑——不用你告诉它点哪儿、也不用你会命令行。

**它不是**：远程桌面（那你得自己动手）、命令行转发（那得你会命令）、
多用户 bot 服务（那是另一套产品）、SaaS（那数据要出门）。

---

## 一、产品全景

![产品全景](diagrams/product-01-context.svg)

三个关键约束直接来自这张图：

1. **手机和电脑之间不需要任何网络穿透。** 手机走微信、电脑长轮询腾讯——
   **iLink 本身就是那个现成的公共中继。** 这也是"在外面遥控家里电脑"零成本的原因。
2. **管家必须住在一台你自己的机器上**，因为要动你的文件。
3. **模型是主人自备的**，数据只经过主人自己的模型账号。

## 二、词汇表（先统一语言，后面全用它）

| 概念 | 英文 | 定义 |
| --- | --- | --- |
| **主人** | Owner | 唯一的用户。**IM 账号就是身份**，没有注册登录 |
| **管家** | Butler | 产品的拟人化称呼。本质是 agent + 记忆 + 权限 |
| **中枢** | Hub | 主人的一台常开设备。**唯一持有 IM 登录态**，负责认人、路由、审批、记忆 |
| **节点** | Node | 被遥控的电脑。**活在这里干**（文件、命令都在本机） |
| **通道** | Channel | 接入的 IM。微信优先，后续飞书/Telegram |
| **链路** | Link | 中枢 ↔ 节点 之间的传输方式（局域网 / Tailscale / SSH…） |
| **能力** | Skill | 管家能做的一件事（找文件、整理、发通知、定时…） |
| **回合** | Turn | 主人说一句 → 管家做完 → 回一句 |

> **为什么必须"唯一持有登录态"**：一个 IM 账号的 bot 只能有一个收信方。
> 两个进程同时收信会互相抢消息、游标互相打架（M0 实测过）。

## 三、五层能力模型

![五层能力模型](diagrams/product-02-layers.svg)

用户感知到的产品从外往里是这五层，**每一层坏掉，用户体验都塌**：

| 层 | 内容 | 失败后果 |
| --- | --- | --- |
| ① 接入 | 安装器 · 引导页 · 扫码 | 小白第一道坎，卡这里产品就不存在 |
| ② 对话 | 文本 · 语音 · 图片 · 文件 · 引用 | **唯一不能让的地方**，卡这里后面全白搭 |
| ③ 能力 | 找东西 · 整理 · 执行 · 提醒 · 总结 | 决定"有没有用" |
| ④ 设备 | 路由 · 别名 · 在线状态 | 差异化所在 |
| ⑤ 信任 | 审批 · 记忆 · 审计 · 隐私 | 决定"敢不敢长期用" |

**判断优先级的原则**：③ 决定"有没有用"，⑤ 决定"敢不敢用"，② 是底线。

## 四、用户旅程

![首次使用旅程](diagrams/product-03-journey.svg)

| 步 | 用户做什么 | 产品做什么 | 不能出现的东西 |
| --- | --- | --- | --- |
| 1 | 双击安装包 | 装依赖、起服务、开引导页 | 终端、npm、git |
| 2 | 贴一下模型 key | 本地页面：去哪儿拿写着、粘一个框、存进 0600 的凭据库 | 手写 YAML、API 文档 |
| 3 | 手机微信扫二维码 | 自动换码的扫码页（码只活 90 秒） | 端口、回调地址 |
| 4 | 回一个"你好" | 认主、建会话、回一句自我介绍 | 配置文件 |
| 5 | 说第一件真事 | 干活 | 工作目录、权限设置 |

> 第 2 步以前是"（可选）填模型 key：引导申请 → 复制 → 粘贴"，落在用户身上
> 是一份要改的 YAML（provider、baseURL、models、contextWindow…）。**那一步
> 小白做不到**，所以现在产品自带一个默认模型通道，用户只提供 key 值本身 ——
> 一个输入框，别的都由程序写。

> **第 2 步不止一次**：用 Telegram 时，管家会**先**问一次机器人 token（同一个页面、
> 同一个"粘一下"的动作），再问模型 key —— 两样都不写进 `config.json`，
> 都落在只有本人能读的文件里（0600）。
>
> **第 1 步现在的样子**：`install.sh` 已经能一行装完（查/下 Node 并校验 → 装进
> `~/.butler/prefix` → 起引导页），macOS 上还带一个 `install.command` 可以双击
>（第一次要右键 → 打开：我们没买 Apple 的签名证书）。真正的 `.dmg` / `.exe`
> 要等签名那一步 —— 那一步要钱，不是要技术。

**验收标准**：一个不懂技术的人，**不用问任何人**能独立走完。

### 日常

```
「昨天那个 PPT 发我」          → 找到文件，发过来
「把下载文件夹清一下」         → 先报清单，确认后动手
「这几张图帮我按日期归档」      → 收图 + 操作 + 回报
「明早 9 点提醒我交周报」       → 定时任务
```

## 五、四个核心机制

![四个核心机制](diagrams/product-04-mechanisms.svg)

### 1. 审批：默认保守，越用越松

- 破坏性 / 对外操作**默认都要问**（删除、覆盖、发消息给别人、改系统设置）
- 主人可以授权"这类以后不用问了" → 写进记忆
- **超时 = 拒绝**（不问就不做，不做错事）
- **绝不静默执行不可逆操作**

> 这是"敢不敢把电脑交出去"的答案。**配置文件和白名单不可能是小白的防线**，
> 所以审批必须是**产品化的、在对话里的**。

**已经落地的**：第一条和第三条 —— dsh 在做敏感操作之前会把问题挂出来，管家把它
问进微信（`允许` / `不许` / `待批`，见 [新手引导](GETTING-STARTED.md)）；没人答就
到点按"不许"结算，一笔一笔落在 `~/.butler/state/approvals/approvals.jsonl` 里。
编号只按主人**看过的那份清单**算：清单变了就重新念一遍，绝不拿旧编号猜是哪一件。

这根线**一头在 dsh 子进程里、一头在管家进程里** —— 离线测不到「真接上了没有」，
所以 `butler doctor` 会在用户的机器上把它查一遍（会问吗 / 有人接吗 / 落得下盘吗）。

**同一批自检，微信里也问得到**：回一句「自检」，管家把这一圈能力位挨个问一遍（问的就是
同一批 `check()`），用人话回给主人。理由很实在 —— 出事的时候，不懂技术的主人手上只有微信，没有终端。

这一层有一条不许变的规矩：**不许报假的绿**。某层的 `check()` 抛了、返回的不是一份检查清单、压根没提供自检 —— 都必须如实说出来。最坏的一种错法是把"没查成"说成"都正常"：主人正是拿这份
报告判断要不要找人帮忙。

**第二条"这类以后不用问了"做出来了**：回「以后这类都行 2」就把这一类记进
`state/grants.json`（0600）——「授权」看得见、「取消授权 1」收得回，靠它放行时账本写
`by: 'grant'`（**绝不冒名**写成"主人当场点的头"）。

**能收窄的维度只有时间**：可以回「以后这类都行 2，一小时」（也认 30 分钟 / 两小时 /
一天 / 3 天，最多 7 天），到点**自动回到"每次都问"**，不用主人记着来收。
为什么不去细抠"只允许某条命令"：按命令前缀授权是个陷阱 —— 「以后 `ls` 不用问」挡不住
`ls; rm -rf ~`，它给的是**假的安全感**，比粗授权更危险。

### 2. 记忆：越用越懂

| 类型 | 例子 | 写入方式 |
| --- | --- | --- |
| **偏好** | "简历都放 Documents/简历/" | 主人明说；或**管家自己在回答里写下** `[[记住: …]]`，内核截下来、当场告诉主人一声 |
| **事实** | "我的工作目录是 ~/work" | 同上 —— **宁可漏认，不可错认**：只认"整行就是标记"这一种写法，一次最多一条 |
| **授权** | "整理下载文件夹不用问" | **只在主人明确同意后**；可以带期限（"就这一个小时"），到点自动作废 |

主人可以随时问"你记得我什么"，也可以"忘掉这条"。

标记本身**绝不漏进微信**：任何位置出现的都会被摘掉 —— 摘得比认得宽。

### 3. 主动：从"应答"到"管家"

- **定时**：每天 8:00 报日程、每周五提醒周报
- **事件**：磁盘满、备份失败、文件变更
- **主动汇报**：长任务完成后主动说一声，不用等问

> 主动是"管家感"的来源，也是**打扰的来源**。默认克制：主动消息有配额，
> 且主人一句"别在半夜发"就能关掉。

### 4. 多设备：不做隐式猜测

- 设备有**别名**（"家里那台""公司电脑"），主人可以自己起名
- **默认目标是中枢所在的那台**（最常用）
- **显式指定才跨设备**——不做隐式猜测
- 每台设备显示**在线/离线**；离线时直接说"那台电脑现在关机了"，不硬试

## 六、交互形态

![交互形态](diagrams/product-05-interaction.svg)

**核心原则：纯对话，零菜单。** 所有能力都通过说话触达。

```
┌──────────────────────────────────┐
│ 管家                              │
├──────────────────────────────────┤
│ ↩ 昨天那个 PPT 发我               │  ← 引用原问题（协议无原生引用）
│ 找到了，发你最新的那版。           │
│ 📎 季度汇报_2026Q3.pptx           │
│                                  │
│ ↩ 把这个文件发给张总              │
│ 要发给「张总」，确认吗？           │  ← 对外操作默认要问
│                                  │
│ [图片]                            │
│ 这是发票，金额 1280，要我记到      │  ← 收图能力
│ 报销台账吗？                      │
└──────────────────────────────────┘
```

**输入形态**：文本、语音（微信服务端已转写，白捡）、图片、文件、引用。

**逃生舱**（不确定时的兜底，**不主动教，但查得到**）：

```
/help       能干什么
/devices    管着哪几台，在线吗
/memory     你记得我什么
/forget x   忘掉某条
/stop       别干了
```

> **为什么用斜杠命令而不是按钮**：微信个人号不能发按钮。
> 斜杠命令是**唯一可行的结构化入口**，但它必须能"看不懂也不影响用"。

## 七、产品边界（明确不做）

| 不做 | 为什么 |
| --- | --- |
| **多用户 / 多人共用** | 定位是"你自己的管家"。多用户要身份、隔离、配额、防滥用四件事，且与"数据不出机器"冲突 |
| **托管 SaaS** | 同上。且"遥控电脑"必须有一台你自己的机器持有登录态 |
| **逆向 hook 微信客户端** | 版本升级就崩，封号风险高 |
| **通用 GUI 自动化**（截图+模拟点击） | 慢、脆、霸占屏幕，几十步未必成。**例外**：定死坐标的单一用途脚本 |
| **全平台一次铺开** | 先 macOS（M0 已验证），Windows/Linux 按需补 |
| **自建中转服务器** | 跨网借 Tailscale；数据不出机器 |
| **替代品式功能堆砌**（天气、新闻…） | 那些是"技能"，不是产品。管家感来自"替你把电脑上的事办了" |

## 八、与替代方案的差异

| 替代 | 它的形态 | 我们的不同 |
| --- | --- | --- |
| 远程桌面 | 你自己动手 | **你说要什么，它动手** |
| SSH / 命令行转发 | 你会命令 | **说人话** |
| ChatGPT 类 App | 只能聊 | **能真的操作你的电脑** |
| 定时脚本 / 自动化工具 | 要预先编排 | **临时起意也能办** |
| 企业微信机器人 | 要装、要认证、收不到你私人微信 | **个人微信，扫码即用** |
